01 방향성

무엇을 만들고, 무엇을 만들지 않나

EA SPORTS FC는 수백 명이 매년 만드는 게임입니다. 같은 방식으로 경쟁하면 이길 수 없으니, 작은 팀이 잘할 수 있는 부분에 집중합니다.

만드는 것

  • 패스 한 번, 슛 한 번의 조작감을 최우선으로 다듬기
  • 똑똑하게 움직이는 팀 AI: 빈 공간 침투, 압박, 커버
  • 약팀을 맡아 키우는 클럽 육성 모드
  • 모바일에서도 편한 터치 조작
  • 팀·선수 이름과 유니폼을 바꾸는 에디터

만들지 않는 것

  • 실제 구단·선수·리그의 이름, 엠블럼, 얼굴 (라이선스 문제)
  • 실사 그래픽과 모션캡처 수준의 애니메이션
  • 돈을 쓸수록 강해지는 선수 뽑기(가챠) 구조
  • 초기 버전의 온라인 대전 (기반을 다진 뒤 추가)

핵심 재미 세 가지

  1. 내가 만든 골: 원투 패스, 스루패스, 감아차기로 직접 만들어 내는 득점 장면
  2. 읽히는 상대: AI가 납득할 만하게 움직여서, 이기면 내가 잘했다고 느껴지는 경기
  3. 키우는 맛: 무명 선수가 시즌을 거치며 에이스로 성장하는 과정

04 선수

선수 능력치

능력치는 6개로 단순하게 시작합니다. 각 수치는 실제 물리값에 바로 연결되어, 숫자가 경기 안에서 체감되도록 합니다.

능력치범위경기에서 바뀌는 것
스피드1–99최고 속도(약 6.5~9.5 m/s)와 가속
드리블1–99공을 몸에 붙이는 거리, 방향 전환 시 공을 놓칠 확률
패스1–99패스 방향·세기의 오차 범위
슈팅1–99슛 최고 속도, 조준 오차, 감아차기 회전량
수비1–99태클 성공 판정 범위, 가로채기 반응 속도

골키퍼는 별도로 반응·다이빙·위치선정 3개 능력치를 씁니다. 포지션(GK·DF·MF·FW)은 AI가 맡는 역할을 정합니다.

05 AI

AI 설계

축구 게임의 품질은 AI가 결정합니다. 내가 조작하지 않는 21명이 어떻게 움직이느냐에 따라 게임이 살아 보이기도 하고 바보 같아 보이기도 합니다. 그래서 AI는 두 층으로 나눕니다.

팀 AI · 어디에 있을까

  • 포메이션 기준 위치를 공의 위치에 따라 밀고 당김
  • 공격 시 대형을 넓히고, 수비 시 좁히고 라인을 내림
  • 팀 전술 설정: 점유 / 역습 / 강한 압박
  • 슛·패스 길을 계산해 "빈 공간"에 선수를 보냄

개인 AI · 무엇을 할까

  • 공 소유: 패스, 드리블, 슛 중 기대값이 가장 높은 선택
  • 공격 지원: 패스 받을 각도 만들기, 침투
  • 압박: 가장 가까운 1~2명이 공 가진 선수에게 접근
  • 마킹·커버: 위험한 상대를 따라가고 뒷공간 지키기
  • 복귀: 역습을 당하면 기준 위치로 전력 질주

난이도는 AI의 판단 속도, 실수 확률, 판단할 때 살펴보는 선택지 수로 조절합니다. 능력치는 건드리지 않아서, 난이도가 높아져도 AI가 반칙처럼 느껴지지 않게 합니다.

07 기술

기술 스택

결정: 두 개의 프로젝트로 진행

  • 1단계 · 웹 버전 (web/): TypeScript + Three.js. 링크 하나로 PC와 모바일 브라우저에서 바로 플레이하며 재미를 검증합니다.
  • 2단계 · Unity PC 버전 (unity/): 웹 버전에서 검증한 조작감, 공 물리, AI, 규칙을 바탕으로 Unity(C#)에서 새로 만드는 별도 프로젝트입니다. 애니메이션과 그래픽 품질을 높이고 Steam 출시를 노립니다.
  • 두 프로젝트는 이 기획서(docs/)를 공유합니다. 웹 버전의 게임 로직(물리, AI, 규칙)은 화면 그리기 코드와 분리해 두어, Unity로 옮길 때 그대로 C#으로 바꿔 쓸 수 있게 합니다.

아래 비교표는 엔진을 고를 때 검토한 내용입니다.

선택지장점단점
TypeScript + Three.js1단계브라우저에서 바로 실행되고, PC·모바일 동시 대응. Steam은 Electron/Tauri로, 앱스토어는 Capacitor로 포장. 코드 중심이라 Claude Code와 함께 빠르게 반복하고 브라우저 자동 테스트도 가능저사양 폰에서는 최적화 필요. 애니메이션 편집 도구가 적음
Unity2단계모바일·PC 출시 경험이 가장 많이 쌓인 엔진. 애셋스토어에 축구 애니메이션 등 자료가 많음에디터 중심 작업이라 코드만으로 다루기 어려움. 요금 정책 변동
Godot 4무료 오픈소스이고 가벼움. 2D·간단한 3D에 강함모바일 3D 성능과 생태계가 상대적으로 작음
Unreal그래픽 품질 최상소규모 팀과 모바일에는 무겁고 과함

웹 버전 구성 세부

  • 렌더링: Three.js, 선수는 로우폴리 3D 모델 + 무료 애니메이션 라이브러리(달리기, 킥, 태클, 세리머니)
  • 공 물리: 직접 구현. 중력, 공기 저항, 바운드, 회전에 의한 휘어짐(감아차기)만 다루면 되므로 범용 물리 엔진보다 가볍고 조절하기 쉬움
  • 게임 루프: 60Hz 고정 시뮬레이션 + 렌더링 분리. 나중에 온라인과 리플레이를 붙이기 쉬움
  • 코드 구조: 게임 로직(물리·AI·규칙)과 화면(Three.js)·입력을 분리. 로직은 브라우저 없이도 테스트 가능하게
  • 빌드·배포: Vite로 빌드해 웹에 올림. 링크 하나로 PC·모바일에서 플레이
  • 성능 목표: PC 60fps, 중급 안드로이드폰 최소 30fps
08 로드맵

개발 단계

단계마다 "완료 기준"을 둡니다. 기준을 넘기 전에는 다음 단계로 가지 않습니다.

  1. M0

    프로토타입

    경기장, 선수 1명, 공 물리, 드리블·패스·슛.

    완료 기준: 혼자 공을 몰고 가서 골을 넣는 것이 재미있다.

  2. M1

    5대5 경기

    팀 AI 기본형, 선수 전환, 골·킥오프·점수·타이머, 빠른 경기 모드.

    완료 기준: AI 상대로 5분 경기가 끝까지 자연스럽게 진행된다.

  3. M2

    11대11 정식 경기

    포메이션, 골키퍼 AI, 라인 아웃·코너·골킥·파울·오프사이드, 로컬 2인.

    완료 기준: 처음 해보는 사람이 "축구 게임 같다"고 느낀다.

  4. M3

    모바일 대응

    터치 조작, 보조 모드, 화면 UI, 성능 최적화.

    완료 기준: 중급 안드로이드폰에서 30fps 이상으로 한 경기를 끝낼 수 있다.

  5. M4

    콘텐츠

    가상 리그 32팀, 클럽 육성 모드, 컵 대회, 에디터, 효과음과 관중 소리.

    완료 기준: 한 시즌을 처음부터 끝까지 플레이할 수 있다.

  6. M5

    웹 버전 공개

    웹 버전을 링크로 공개하고 피드백을 모읍니다. 온라인 1대1은 반응을 보고 결정합니다.

    완료 기준: 외부 테스터가 PC와 폰에서 큰 버그 없이 플레이한다.

  7. U1

    Unity PC 버전 시작

    별도 프로젝트로 시작합니다. 웹 버전의 로직을 C#으로 옮기고, 선수 애니메이션과 그래픽을 새로 만듭니다. 목표는 Steam 출시입니다.

    완료 기준: 웹 버전과 같은 11대11 경기가 Unity에서 더 자연스러운 움직임으로 돌아간다.

09 리스크

위험 요소와 대응
